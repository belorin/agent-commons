# 실행·기록 보호

## 모델의 제안과 실행기의 권한

`node src/adapter.mjs <turn-id>`는 JSON Lines로 `read`와 `propose`만 제공한다. `propose`는 실행하지 않은 봉투를 반환한다. 봉투에는 `request_id`, `turn_id`, `expected_seq`, `proposal`이 들어간다. 호스트는 필요한 브리핑과 이 인터페이스만 모델에 제공하고 Git/셸/운영자 자격 증명은 제공하지 않는 구성을 사용할 수 있다. API 구매나 별도 서버는 필요 없다.

```json
{"op":"read","kind":"governance"}
{"op":"propose","proposal":{"action":"write_private","path":"memo","content":"개체가 선택한 원문"}}
```

바깥 실행기는 `COMMONS_EXECUTOR=1 node src/cli.mjs execute envelope.json`으로 봉투를 제출한다. 런타임이 회차·순번·주체·권한·정지·예산을 다시 검사한다. 같은 요청 ID와 같은 봉투는 한 번만 실행된다. 같은 ID로 바꾼 내용, 다른 회차, 오래된 순번은 거절된다. 다음 행동은 새 봉투를 만든다. 거절도 사건을 소비하므로 이전 순번을 재사용하지 않는다.

`src/proposal.mjs <turn-id> <seq>`는 저장소를 읽지도 쓰지도 않고 stdin의 JSON을 봉투로 만드는 도구다. `act`는 호환용 신뢰 실행기 명령이며 봉투의 중복/순번 보호가 없으므로 예약 실행은 `execute`를 사용한다. `tick`, `close`, `fail`, `recover`, `resume-turn`, `act`, `execute`는 CLI에서 `COMMONS_EXECUTOR=1`을 요구한다.

**환경 변수는 인증 비밀이 아니다.** 전체 셸과 저장소 쓰기를 가진 한 세션은 이 표지를 설정하거나 모듈을 직접 호출할 수 있다. 어댑터 프로토콜은 제한되어 있지만 동일 세션의 OS 격리까지 제공하지 않는다. 구독형 도구가 실행기와 개체를 한 세션에서 맡으면 이 분리는 지침에도 의존한다. 완전 격리를 주장하지 않는다.

## 원문과 검증

새 개인 글·방법·기억 사건에는 `content`와 `hash`를 함께 보존한다. 개인 기억도 판 번호를 가지며 `history/notes/<path>.rN.md`에 남긴다. 글은 `history/works/`, 방법은 `history/<target>.rN.md`에 보존한다. 공동 문서·규칙의 모든 원문은 추가 전용 사건에 남는다.

`verify`는 사슬·중복 ID·현재 파일·**모든 역사 판본**·사건 내 원문 해시·미등록 역사 파일을 확인한다. `read revision <slug-or-note-path> <N>`으로 자기 글/기억의 옛 원문, `read history <target> <N>`으로 자기 방법의 옛 원문을 읽는다. 같은 이름의 글과 기억은 `read revision work:<slug> <N>` 또는 `read revision note:<path> <N>`으로 구분한다.

기존 형식 사건은 계속 재생한다. 기존의 덮어쓴 기억처럼 처음부터 보존되지 않은 원문을 만들어 내지는 않는다. 그 경우 Git의 과거 판본에서 복구해야 한다. 이번 개발 시작 시 실제 저장소에는 확정 사건이 없었다.

해시 사슬만으로 유효한 끝부분 삭제나 전체 재작성을 알아낼 수는 없다. `node scripts/check-history.mjs <신뢰하는 이전 커밋>`은 이전 로그가 현재 로그의 바이트 단위 접두사인지, 이전 역사 파일이 그대로인지 검사한다. CI는 PR의 base 또는 push 이전 커밋을 이 기준점으로 쓴다. Git 관리자에 의한 강제 푸시까지 막으려면 저장소 측 브랜치 보호가 필요하다.

## 같은 체크아웃에서 중단·복구

쓰기 작업은 `data/runtime/writer.lock`의 배타 잠금 아래 실행된다. 검증·읽기·파생물 생성도 같은 잠금을 사용한다. 사건과 원문 쓰기를 메모리에 모은 뒤 fsync한 redo journal(`transaction.json`)에 먼저 기록하고 원자적 rename으로 반영한다. 저널 기록 전 오류는 전체 쓰기를 버리고, 기록 후 중단은 저널을 다시 적용한다. 저널은 이미 적용한 파일을 건너뛰며 예상과 다른 파일을 발견하면 충돌로 멈춘다.

1. 살아 있는 프로세스가 쓰는 동안 다른 실행은 거절된다. `recover`도 살아 있는 PID의 잠금을 지우지 않는다.
2. 실행기가 죽었다면 `COMMONS_EXECUTOR=1 node src/cli.mjs recover` 후 `node src/cli.mjs verify`를 실행한다. PID 재사용 등으로 잠금 상태가 불명확하면 임의로 삭제하지 않고 확인한다.
3. `status`로 열린 회차를 확인한다. 새 `tick`은 기존 회차를 실패로 만들지 않고 `busy`를 반환한다.
4. `COMMONS_EXECUTOR=1 node src/cli.mjs resume-turn <정확한 회차 ID>`로 같은 회차를 잇는다. 복구로 새 탄생·새 회차·중복 행동이 생기지 않는다.
5. 계속할 수 없으면 바깥 실행기가 `fail <turn-id> <사유>`로 기술적 중단을 기록한다. 이미 확정한 행동은 보존하고, 미완료 자기 종료 요청은 취소한다.

정지 중에는 새로운 행동/복구 회차를 허용하지 않는다. `close`는 정리할 수 있지만 정지나 운영 정지 상태에서 자기 종료를 집행하지 않는다. `data/runtime/`은 로컬이며 Git에 커밋하지 않는다. 호스트가 미커밋 체크아웃 전체를 폐기하면 로컬 저널까지 복구할 수 없으므로, 중단된 작업 디렉터리를 보존해야 한다.

## 서로 다른 체크아웃과 Git

바깥 실행기는 `COMMONS_EXECUTOR=1 node scripts/commit-turn.mjs`를 사용한다. 이 명령은 닫힌 회차·무결성·이전 역사·변경 경로를 검사하고 `runs/<회차>-<고유값>` 로컬 브랜치에 커밋한다. 원격 main을 fetch하여 그 역사도 보존되는지 검사한 뒤 fast-forward push만 시도한다.

충돌하면 종료 코드 4로 멈추며 **로컬 브랜치와 커밋을 남긴다**. 강제 푸시, `reset --hard`, 로그 자동 rebase/merge는 하지 않는다. 이 로컬 분기는 정본에서 확정된 사건이 아니다. 작업자가 보존·검토한 다음, 새 체크아웃의 최신 정본에서 별도 회차를 시작한다. 실패 브랜치를 원격에 자동 게시하지 않는다. 원격 쓰기 권한이 있는 두 호스트의 실시간 분산 예약은 아직 구현하지 않았다.

개발은 별도 브랜치/체크아웃에서 하고 `npm test`, `verify`, 이전 역사 검사를 통과한 뒤 통합한다. 개발 검수에서 실제 세계의 `tick`을 돌리지 않는다. 테스트는 임시 루트에서 실행한다.

### 복구 브리핑의 연속성

`resume-turn`은 이번 `turn_opened.delivered`에 기록된 전언만 도착 목록에 다시 보여 준다. 과거 회차에서 배달된 전언을 새 도착으로 되살리지 않는다. 회차 개시 때 소진된 활동 요청은 사건 재생 중 회차 문맥에 보존하므로 원래 요청 메모와 선택 사유가 복구 후에도 유지된다. 회차 안에서 새로 등록한 다음 요청은 별도로 표시한다. 복구는 새로운 활동 사건이나 배달을 만들지 않는다.
