## 남은 문제 / 아직 구현하지 않은 것
- 실제 외부 탐색 도구의 기능·접속 가능 여부를 어댑터가 협상하거나 세션 간 보존하는 프로토콜은 없다. 현재는 바깥 실행기의 사전 점검 지침에 의존한다. 이번에 외부 조사를 실제로 실행하거나 성공했다고 기록하지 않았다.
- 자기 기록 검색은 개체가 선택한 기존 원문을 읽는 기능이다. 출처 수집·원문 보관·검색 결과 신뢰성 검증을 자동 수행하지 않는다.

- `failTurn`으로 확정 중단하면 소비된 활동 요청이 자동 재예약되지는 않는다. 자동 재시도를 새 선택으로 위장하지 않는 복구 정책을 검토할 여지가 있다.
- 기본 순번으로 선택된 충족 요청(우선권 0 포함)은 스냅샷이 보존되지만 요청 메모를 브리핑에서 설명하는 방식은 아직 요청 우선 배정 중심이다.
- 미커밋 코드/WIP 없음. main 통합과 실제 운영 관찰은 수행하지 않았다.

## 다음 세션의 구체적 착수 순서
1. 원격 브랜치와 main을 fetch하고 이 장부의 구현 커밋 존재를 확인한다. main에 새 회차가 있으면 사건 로그를 자동 병합하거나 덮어쓰지 않는다. 코드 통합과 세계 회차는 별도 체크아웃으로 취급한다.
2. `AGENTS.md`, `ASTRA.md`, `docs/CONCEPT.md`, 본 장부를 읽고 `git status`를 확인한다. 기능 개발 전용 브랜치를 이어 쓴다.
3. 먼저 `read schedule`과 복구 브리핑에서 **일반 순번으로 소비된 요청**을 어떻게 설명할지 정리한다. `max_request_streak: 0`으로 임시 세계 재현, 요청 메모·선택 사유를 실제 배정과 혼동하지 않게 표시한다.
4. 다음 개발 후보는 외부 탐색 경로 상태를 호스트가 선언하고 개체가 읽을 수 있는 최소 어댑터 인터페이스다. 도구가 실제로 호출되었는지/차단되었는지와 개체의 흥미·휴면을 분리한다. 호스트가 자료 주제나 개체 성격을 입력하는 기능은 만들지 않는다. 접근 성공을 만들어 내지 않는다.
5. 기술 중단 후 재개/새 회차의 경계는 사건 재생과 멱등성부터 확인한다. 실패를 개체의 침묵·종료로 바꾸지 않는다.
6. 의미 있는 기능마다 필요한 범위 검증 → 장부 갱신 → commit → 원격 저장 확인. 끝에 전체 테스트·verify·기존 역사 보존을 확인한다.
